# MeshTalk — Roadmap, Risks, and Feature Status

A feature is listed as **Implemented** only when the code exists and automated
tests cover it. "Verified" below means verified on macOS arm64, the only
platform these tests have run on so far. Windows and Linux are configured in CI
but have not run yet (the repository has not been pushed).

### Partially implemented

- **Cross-platform packaging.** electron-builder targets (DMG, NSIS, AppImage,
  deb) and the release workflow are configured. Only the macOS arm64 package
  was built and smoke-tested, including with fuses. Signing and notarization
  need your certificates. There is no app icon yet.
- **Network modes.** Only Mode A (LAN-only) exists. Settings explains B and C
  but they can't be selected.
- **Network change handling.** Address changes are detected by polling, and
  discovery is restarted. Long-lived calls rely on ICE restart, which has only
  been tested on loopback.

### Not implemented (planned)

| Item                                                                                                                                                                                        | Why not yet / what it needs                                                                                                                            |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Account/signaling server (Mode B/C)**: verified email, password reset (Argon2id), sessions & device list, device codes, cross-network signalling, TURN credentials, org admin & audit log | No JDK on the development machine; designed in ADR-0004. Nothing in the desktop app pretends to have it.                                               |
| Connecting across networks (STUN/TURN, WebRTC data channels for files)                                                                                                                      | Depends on the server.                                                                                                                                 |
| End-to-end encrypted store-and-forward relay                                                                                                                                                | Needs the E2E protocol decision (threat model).                                                                                                        |
| Multi-device accounts / history sync between one person's devices                                                                                                                           | Needs an E2E multi-device design (MLS candidate).                                                                                                      |
| Group calls                                                                                                                                                                                 | Mesh ≤ 4 or SFU; separate phase.                                                                                                                       |
| Encrypted backups / encrypted database at rest                                                                                                                                              | Today backups and the DB are plaintext (the UI says so); only the device key is protected. Candidate: SQLCipher via `better-sqlite3-multiple-ciphers`. |
| Auto-update                                                                                                                                                                                 | Needs a signed update feed; must stay opt-in.                                                                                                          |
| QR-code pairing, history for newly added group members, conflict-free concurrent admin edits                                                                                                | Documented limitations.                                                                                                                                |

## Technical risks

| Risk                                                             | Status / mitigation                                                                                                                        |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Email identity in LAN-only mode                                  | Shown as "unverified" everywhere. Trust is the device fingerprint.                                                                         |
| Discovery blocked (client isolation, VLANs, multicast filtering) | Add-by-address and a layered connection test with OS-specific advice. QR pairing not built.                                                |
| NAT traversal across networks                                    | Not supported in Mode A by design. Needs the server + TURN.                                                                                |
| Offline messaging                                                | Sender outbox only, visible in the UI. No relay.                                                                                           |
| Cross-device sync                                                | Each device is its own identity.                                                                                                           |
| Group consistency                                                | Snapshot versions from admins. Concurrent edits by two admins can drop one change (ADR-0005).                                              |
| Group calling                                                    | Not built.                                                                                                                                 |
| E2E for relays                                                   | No relay exists, so nothing is exposed. Decision still open.                                                                               |
| File-transfer reliability                                        | Covered by per-chunk/whole-file hashes, resume and atomic finalize tests. Real-network throughput still to be measured on target hardware. |
| Native ABI (better-sqlite3)                                      | Rebuilt on install; DB tests run under Electron's Node.                                                                                    |
| Linux secret storage                                             | Detected and warned about in Network → This device.                                                                                        |
| Real-world WebRTC                                                | E2E uses synthetic devices on one machine. Real cameras, microphones and networks need the manual matrix in `docs/testing.md`.             |
